引入“突发性”（Burstiness）检测：

原理：AI 生成的文本通常句子长度比较平均，节奏单一。而人类写作的句子长短不一，节奏感强。

算法：计算段落中“句子长度的标准差”。如果标准差高（长短句交替），认为这是人类特征，强行扣除 AI 分数。

加大“疑罪从无”力度：

温度系数：从 1.8 提升到 2.0。

指数惩罚：从 2.5 次方提升到 3.5 次方。这样就意味着如果模型只有 80% 的把握，经过计算后会被压到 45% 左右（判定为人类）。只有模型有 95% 以上把握时，才会判定为 AI。

标点丰富度奖励：人类写作往往会使用更丰富的标点（如括号、分号、破折号），而 AI 倾向于使用逗号和句号。如果检测到丰富标点，给予“人类加分”。

### <span style="color:#1E90FF;">**V 6.2**

Bug 修复公告

1. 双显卡笔记本 CUDA 休眠问题
收到用户反馈：部分未配备独显直连功能的笔记本电脑，尽管系统可正常识别独立显卡，但由于 CUDA 处于休眠状态，软件无法调用 GPU 进行计算，导致所有检测结果均为 0%。此问题现已修复。
现在，在双显卡笔记本环境下，软件会首先尝试唤醒 CUDA；若唤醒失败，则自动切换至 CPU 模式继续运行。

附：自行验证/临时处理方法
如您希望手动确认或规避该问题，可以尝试以下方式：

禁用核显驱动，或彻底关闭核显（仅保留独立显卡）；

开启独显直连模式（若硬件支持）。
验证方法：打开“设备管理器” → “显示适配器”，若列表仅显示独立显卡，则表示核显已被成功屏蔽。

2. GPU 不可用时与 TraceLess 联机的问题
有用户反馈，当 GPU 不可用时，与 TraceLess 联机后无法正常检测 AI 率。该问题的根本原因与上述 CUDA 休眠问题相同，现已一并修复。
现在，当您在 Deepveri 中切换为 CPU 模式后，TraceLess 也会正常使用 CPU 执行 AI 检测。

补充说明
以上问题均出现在笔记本电脑的显示混合模式场景下，台式机（通常仅有独立显卡或未启用混合模式）几乎不受影响。

3. 拖拽文件相关问题
修复了拖拽文件操作相关的已知问题。

### <span style="color:#1E90FF;">**V 7.0**

v7.0 是本软件迄今为止最大的一次底层架构升级。推理引擎从 PyTorch + CUDA 全面迁移至 ONNX Runtime + DirectML，实现了更广泛的 GPU 兼容性、更小的发行体积、以及更健壮的自动容错机制。

一、推理引擎重构：PyTorch → ONNX Runtime

背景： 旧版依赖 PyTorch + CUDA，仅支持 NVIDIA 显卡，且 torch 及依赖体积庞大（约 2GB+），对 AMD / Intel 显卡用户不友好。

变更：

模型格式统一为 model.onnx + tokenizer.json，推理引擎切换为 ONNX Runtime

GPU 加速改用 DirectML（Windows 原生 GPU API），彻底摆脱 CUDA 生态

移除 torch、transformers 等重型依赖，发行体积大幅缩减

受益：

NVIDIA / AMD / Intel 全系显卡均可享受 GPU 加速（只需 DX12 驱动支持）

软件包体积缩小约 70%

推理性能与旧版持平或更优

二、GPU 自动回退双保险

第一层：会话创建时回退

若 DirectML GPU 会话创建失败，自动回退 CPU，不会崩溃。

第二层：运行时动态回退

GPU 推理中途遇到掉驱动（TDR）、显存耗尽等错误时，立即捕获并切换 CPU 重试当前段落，不丢失检测进度。

用户可感知的提醒

颜色 | 含义

绿色 | DirectML GPU 加速

黄色 | CPU 运算模式 (DirectML 不可用) 或 CPU 运算模式 (用户强制)

红色 | GPU 不稳定已自动切断

控制台同时显示警告文字和性能提示（强制 CPU 约 10 倍以上耗时）。

三、共享推理会话

GUI 和 API 共享同一个 ONNX 会话 + 分词器（线程安全，双重检查锁）。切换 GPU/CPU 模式时自动重建，两端同步生效。

四、API 微服务改进

删除与 core_engine 重复的工具函数，统一从核心引擎导入

API Worker 复用共享 ONNX 会话，不再独立加载模型

新增 30 秒请求超时保护

设备切换时无缝重启 Worker

五、启动体验优化

后台线程预加载 ONNX 会话，避免首次检测等待

启动时扫描 DirectML 可用性并读取显卡型号

状态栏显示 引擎就绪 (dml) 或 引擎就绪 (cpu)

六、构建打包改进

控制台进度条显示打包各阶段

模型目录只复制 3 个必需文件，不再全量复制

.spec 精确配置 hidden imports，避免运行时缺模块

七、UI 稳定性修复

重新检测时正确断开旧线程的全部信号，防止串扰

面板切换动画冲突检测与清理，避免闪烁

API 健康心跳指示灯正确响应跨线程信号

八、新增工具

export_onnx.py：PyTorch → ONNX 模型导出脚本

升级注意

v7.0 不再支持 pytorch_model.bin/model.safetensors，请确保 AIGC_Model/ 包含 model.onnx 和 tokenizer.json

如无 ONNX 模型，使用 export_onnx.py 从旧模型转换

需要安装 onnxruntime-directml（已在 requirements.txt 中）

首次启动可能有几秒延迟（DirectML 着色器编译），正常现象

已知问题

Windows 7 不支持 DirectML，只能使用 CPU 模式
